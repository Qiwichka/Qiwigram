# Qiwigram

Анонимный мессенджер. Личка, группы, каналы, медиа со спойлером,
самоуничтожение сообщений. Ставится на телефон как приложение.

Статический сайт без сборки: ни npm, ни webpack, ни установки зависимостей.
Открыл файл — правишь, обновил страницу — видишь. Данные и авторизация живут
в Supabase.

## Устройство

```
index.html            главная: стеклянный бублик над надписью «Свобода слова»
app.html              само приложение — вход и мессенджер на одной странице
assets/js/glass.js    фон главной, сырой WebGL без библиотек
assets/js/config.js   адрес Supabase и публичный ключ
assets/js/db.js       всё общение с базой; выше него SQL не поднимается
assets/js/ui.js       мелкие помощники интерфейса
assets/js/app.js      сборка мессенджера
assets/vendor/        библиотека Supabase, лежит своя, а не с чужого CDN
db/                   схема базы, три файла
tools/serve.js        локальный сервер для проверки
tools/make-icons.ps1  перерисовка иконок приложения
```

## Запуск у себя

```
node tools/serve.js
```

Потом `http://localhost:5173`.

Двойным кликом `app.html` **не откроется**: страница подключает скрипты как
модули, а модули по протоколу `file://` браузер запрещает. Только через http.

## Настройка базы с нуля

В SQL Editor проекта Supabase выполнить по порядку, каждый файл отдельно:

1. `db/schema.sql` — таблицы, права доступа, функции
2. `db/02_overview.sql` — запросы, которые вызывает браузер
3. `db/03_storage.sql` — хранилище фотографий и видео
4. `db/04_e2e.sql` — ключи и сквозное шифрование

Порядок важен. Третий файл отдельно намеренно: редактор выполняет скрипт одной
транзакцией, и если политики хранилища упрутся в права, откатится вся схема.

В настройках Authentication → Providers → Email должен быть **выключен**
`Confirm email`, иначе никто не войдёт с выдуманной почтой.

## Шифрование

Личка и закрытые группы шифруются сквозно. Разбор — в шапке
`assets/js/crypto.js`, там же честный список того, чего шифрование не даёт.
Коротко:

- пара ключей ECDH P-256 заводится при регистрации прямо в браузере
- открытый ключ лежит в профиле, закрытый — в базе, зашифрованный ключом,
  выведенным из пароля через PBKDF2 (310 000 повторений)
- **пароль на сервер не уходит никогда**: Supabase хранит от него хеш,
  а ключ шифрования считается в браузере
- в личке общий ключ выводится из пары «мой закрытый + его открытый»,
  обмена ключами не происходит вовсе
- у группы свой случайный ключ, завёрнутый отдельно под каждого участника
- файлы шифруются целиком перед отправкой; в хранилище лежит мусор

Проверить, что это правда, можно за минуту: открой таблицу `messages`
в панели Supabase. У зашифрованных чатов поле `body` пустое, а в `enc` лежит
`{ iv, ct }` — расшифровать это тем, у кого нет ключа, нельзя.

**Чего шифрование не закрывает:** метаданные (кто с кем и когда), слабый
пароль (ключ защищён им, и перебор по базе никто не остановит), подмену
самого сайта владельцем. Против последнего помогает APK и открытый код.

## Что стоит знать, прежде чем править

**Ключ в `config.js` публичный.** Так устроен Supabase: он попадает в браузер
каждому посетителю. Данные закрывают правила RLS в базе, а не секретность
ключа. Ключ `service_role` в этот файл класть нельзя никогда.

**Вход по нику работает через синтетическую почту** `ник@users.qiwigram.app`.
Supabase Auth умеет входить только по почте, а искать настоящую почту по нику
означало бы отдавать почту любого пользователя любому желающему. Настоящая
лежит в закрытой таблице `user_private`, куда доступ есть только у владельца.
Побочное следствие: восстановление пароля из коробки не работает, нужна
отдельная серверная функция.

**`[hidden] { display: none !important }` в начале `app.css` трогать нельзя.**
Браузер прячет `[hidden]` правилом из своей встроенной таблицы, а она
проигрывает любому авторскому правилу. У заставки, окон и просмотрщика прописан
свой `display` — без этой строки они остаются на экране, будучи скрытыми.

## Приложение для Android

Не обёртка над сайтом в браузере: Capacitor даёт своё окно с файлами
внутри APK. Ни адресной строки, ни свайпа «назад по истории», ни зависимости
от домена — приложение открывается и без сети, до самого входа.

Собирается на серверах GitHub, локально Android SDK не нужен:

```
gh workflow run android.yml -R Qiwichka/Qiwigram
```

Готовый файл — во вкладке Actions, в артефактах сборки. Тег вида `v1.2.3`
дополнительно прикладывает APK к релизу.

Ключ подписи в репозиторий не попадает: `android/app/build.gradle` берёт его
из переменных окружения, а workflow — из секретов. **Ключ терять нельзя:**
Android считает подпись частью личности пакета, и обновление, подписанное
другим ключом, поверх старой версии не встанет.

## Уведомления

Push на Android доставляет только сервис Google, а регистрация в Firebase
требует подтверждения по номеру телефона — того самого, из-за которого
выбран Supabase. Поэтому приложение сторожит переписку само: фоновая
служба (`WatchService.java`) раз в полминуты спрашивает `chat_overview`
и показывает уведомление, когда появилось непрочитанное.

Android не разрешает работать в фоне молча, поэтому в шторке висит
постоянная строчка. Она же выключатель. Цена — расход батареи — названа
человеку до системных окон, а не после.

**Текста сообщения в уведомлении не бывает.** Переписка зашифрована, ключи
живут в браузерной половине приложения, и служба видит только то, что
сообщение есть и от кого. Телеграм в секретных чатах ведёт себя так же.
